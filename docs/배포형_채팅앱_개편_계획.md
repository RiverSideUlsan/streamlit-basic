# 배포형 Streamlit 채팅 앱 개편 계획

## 1. 목표와 범위

대상은 `app2.py`를 시작 파일로 사용하는 채팅 앱이다. Streamlit API 예제 앱인 `app.py`는 이번 개편 범위에서 제외한다.

| 요구사항 | 구현 방향 |
| --- | --- |
| 배포 페이지의 key 등록 | 로그인한 사용자가 자신의 OpenAI API 키를 비밀번호형 입력창에 등록한다. 키가 없으면 채팅과 내역 화면에 들어갈 수 없게 한다. |
| 디자인 리뉴얼 | 로그인 → 키 등록 → 채팅·내역으로 이어지는 단순한 화면 흐름과 일관된 테마를 적용한다. |
| 채팅과 내역 보기 | 세션 목록, 대화 화면, 과거 내역 조회를 제공한다. 기존 이미지 업로드·전송·표시 기능은 제거한다. |
| 로그인과 보안 안내 | SQLite 계정 로그인 화면을 만들고, 채팅 저장 및 민감정보 입력에 관한 안내 문구를 표시한다. |
| 세션당 100개 대화 | 사용자 질문과 AI 답변 한 쌍을 **1개 대화**로 계산한다. 100개를 넘으면 해당 세션의 가장 오래된 대화부터 삭제한다. |
| 최대 10개 세션 | 사용자별로 최근 10개 세션만 유지한다. 새 세션이 11번째가 되면 가장 오래된 세션과 그 대화를 함께 삭제한다. |

이 문서에서 **채팅 세션**은 사용자가 “새 채팅”으로 만드는 저장 단위다. 브라우저 탭마다 생성되는 Streamlit의 실행 세션(`st.session_state`)과 구분한다.

## 2. 현재 코드에서 바꿀 부분

- `app2.py`는 `st.navigation`으로 채팅과 과거 내역을 전환한다. 로그인과 키 등록 페이지를 여기에 추가한다.
- `app2_chat.py`는 `.env`의 `OPENAI_API_KEY`를 읽고, `chat_history.db`의 `messages` 테이블에 모든 사용자의 메시지를 한 줄씩 저장한다. 사용자 구분과 채팅 세션 구분은 없다.
- `app2_chat.py`의 이미지 업로드 다이얼로그, 대기 이미지 상태, Base64 인코딩, 이미지 API 입력을 제거한다. 기존 텍스트 문서 첨부는 유지한다.
- `app2_history.py`는 모든 DB 메시지를 최신순으로 보여 준다. 선택한 사용자의 세션 목록과 해당 세션의 대화만 보여 주도록 바꾼다.
- 현재의 “SQLite 전체 기록 삭제”는 다른 사용자 기록까지 지울 수 있으므로 사용자별·세션별 동작으로 변경한다.

## 3. 화면과 사용 흐름

1. 미로그인 상태: 로그인 페이지와 보안 안내만 보여 준다. 채팅·내역 페이지의 직접 URL 접근도 서버 측에서 막는다.
2. 로그인 완료, 키 미등록 상태: 키 등록 화면을 보여 준다. 키가 입력되기 전에는 OpenAI 요청과 채팅·내역 조회를 실행하지 않는다.
3. 키 등록 완료: 사이드바에서 “새 채팅”, 저장된 세션 최대 10개, “과거 내역”, “키 변경”, “로그아웃”을 제공한다.
4. 채팅 화면: 선택한 세션의 대화를 오래된 순서대로 표시하고, 텍스트 질문과 AI 답변을 한 쌍으로 저장한다. 현재 세션의 대화 수를 `n/100`으로 표시한다.
5. 과거 내역 화면: 본인의 세션을 최신순으로 보고, 선택한 세션의 대화와 생성 시각을 읽기 전용으로 확인한다.

디자인은 Streamlit 기본 컴포넌트와 `.streamlit/config.toml`의 테마 설정을 우선 사용한다. 로그인 화면의 안내 → 키 등록 카드 → 채팅 화면의 사이드바·본문이 같은 색상과 문구 체계를 갖도록 하고, 좁은 화면에서도 버튼과 대화 내용이 읽히게 확인한다. 기존 앱의 이름이나 브랜드 문구가 있으면 유지한다.

로그인 안내 문구 초안:

> 이 앱에 입력한 내용은 외부 AI 서비스로 전송되고 채팅 DB에 저장됩니다. 배포나 접근 제어 설정에 문제가 있으면 대화가 노출될 위험이 있습니다. 주민등록번호, 비밀번호, 결제 정보 등 민감한 정보는 입력하지 마세요.

## 4. 로그인과 API 키 처리

- `users` 테이블에 아이디와 비밀번호 해시를 저장한다. 비밀번호 원문을 DB에 저장하지 않고, 사용자마다 임의의 salt를 더한 PBKDF2-SHA-256 해시를 저장한다.
- 로그인 상태는 Streamlit 세션 상태에만 저장한다. DB 조회·저장·삭제마다 `sqlite:<아이디>`를 조건으로 사용해 다른 사용자의 기록을 조회하지 못하게 한다.
- **기본 키 등록안:** 키는 `st.text_input(type="password")`로 받고, 로그인한 브라우저의 현재 Streamlit 실행 세션에만 보관한다. 새로고침·재접속·로그아웃 후에는 다시 입력한다. 로그아웃 시 키를 세션 상태에서 명시적으로 지운다. DB, URL, 로그, Git 저장소에 키를 남기지 않는다.
- 키의 존재 여부는 화면 버튼의 비활성화만으로 판단하지 않고, 앱 진입과 OpenAI 호출 직전에 서버 코드에서 확인한다. 값이 없으면 안내 화면을 보여 주고 요청을 중단한다. 잘못된 키의 인증 오류는 사용자에게 간단히 알려 주며 키 값을 출력하지 않는다.
- 로컬 개발의 `.env`는 OpenAI API 키에만 사용하며, 사용자 비밀번호나 DB 내용을 넣지 않는다.

키를 재접속 후에도 유지하는 “영구 등록”이 필요하면 암호화 저장소와 암호화 키 관리가 추가로 필요하다. 이번 기본안에는 포함하지 않는다.

## 5. 저장 구조와 제한 적용

배포 후에도 내역을 유지하려면 외부의 영속 데이터베이스를 사용한다. 로컬 `chat_history.db`는 개발·마이그레이션 자료로만 다룬다. Streamlit Community Cloud에서는 로컬 파일 보존이 보장되지 않는다.

| 테이블 | 주요 필드 | 용도 |
| --- | --- | --- |
| `chat_sessions` | `id`, `user_id`, `title`, `created_at`, `updated_at` | 사용자별 채팅 세션 목록 |
| `chat_turns` | `id`, `session_id`, `user_text`, `assistant_text`, `file_name`, `file_content`, `created_at` | 질문·답변 한 쌍과 기존 텍스트 첨부 |

- AI 답변이 성공적으로 생성되면 질문·답변을 `chat_turns` 한 행으로 저장한다. 응답 실패 시 불완전한 한 쌍을 저장하지 않고, 화면에서 재시도할 수 있게 한다.
- 저장 직후 해당 세션의 대화가 100개를 초과하면 `created_at, id` 기준으로 오래된 행부터 초과분을 삭제한다. 같은 DB 작업 안에서 수행해 제한을 일관되게 유지한다.
- “새 채팅”을 누르면 새 세션을 만들고, 사용자별 세션 수가 10개를 초과할 때 `created_at, id` 기준 가장 오래된 세션을 삭제한다. 연결된 대화도 함께 삭제한다.
- AI에 보낼 대화 문맥도 현재 선택 세션의 최근 대화만 사용한다. 다른 사용자나 다른 채팅 세션의 메시지는 섞지 않는다.
- 보존 한도를 UI에 알리고, 새 세션을 만들 때 오래된 세션이 삭제될 수 있음을 사용자에게 표시한다.

기존 `chat_history.db`에는 사용자·세션 정보가 없으므로 기존 1인 대화로 보아 어느 계정에 귀속할지 정한 뒤 옮긴다. 마이그레이션 전 DB를 백업하고, 이미지 데이터는 새 구조로 이전하지 않는다. 기존 DB 파일은 검증 전까지 삭제하지 않는다.

## 6. 구현 순서

1. **배포 환경 확정:** 실제 배포 서비스와 영속 DB를 선택한다. Streamlit Community Cloud의 로컬 SQLite 파일은 재시작·재배포 시 사라질 수 있으므로, 지속 운영에는 외부 DB가 필요하다.
2. **DB 전환:** 사용자·세션·대화 한 쌍의 저장 구조를 만들고, 사용자별 조회 및 100개/10개 제한을 구현한다.
3. **로그인과 키 등록:** `app2.py`의 페이지 접근 조건을 설정하고 로그인·키 등록·로그아웃 화면을 만든다.
4. **채팅 개편:** 이미지 관련 코드를 제거하고 텍스트 채팅, 기존 텍스트 파일 첨부, 세션 선택·새 채팅을 연결한다.
5. **내역 및 디자인:** 사용자별 과거 내역 화면과 테마를 정리하고 보안·보존 안내를 표시한다.
6. **데이터 이관과 배포:** 기존 로컬 기록의 귀속 계정을 확인해 이관하고, 배포 비밀값을 설정한 뒤 배포 환경에서 검증한다.

## 7. 완료 기준

- 로그인하지 않으면 채팅·내역 URL에 직접 접근해도 내용이 보이지 않는다.
- 로그인했어도 키가 없으면 채팅·내역이 동작하지 않고 OpenAI 요청이 발생하지 않는다.
- 서로 다른 두 계정의 세션·대화는 섞이지 않는다.
- 이미지 업로드 UI와 이미지 API 입력 코드가 없다. 텍스트 채팅과 문서 첨부는 동작한다.
- 한 세션에 101번째 질문·답변을 저장하면 1번째 쌍이 사라지고 2~101번째 쌍만 남는다.
- 11번째 세션을 만들면 가장 오래된 세션과 그 대화가 사라지고 최근 10개만 남는다.
- 새로고침·재로그인 후에도 DB에 저장된 대화가 보인다. 브라우저 세션에만 보관한 API 키는 재등록해야 한다.
- 로그인 안내, 키 오류, 기록 없음, 응답 실패 상태가 화면에 자연스럽게 표시된다.

## 8. 구현 전 결정할 항목

1. `key`를 **사용자별 OpenAI API 키**로 해석했다. 서비스 공용 키 또는 앱 접속용 초대 키를 뜻한다면 키 등록 흐름을 다시 정해야 한다.
2. 가입 정책과 허용 대상: 누구나 회원가입할 수 있는지, 관리자만 계정을 만드는지 정한다.
3. 배포 플랫폼과 영속 DB: 현재 저장소만으로는 실제 배포 환경과 DB 서비스가 확정되지 않았다.
4. 기존 로컬 기록을 귀속할 계정과 이미지 데이터의 보관·폐기 방침을 정한다.
